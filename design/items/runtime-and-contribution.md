# 运行时、计分板与贡献值

## 加载与循环

`data/minecraft/tags/function/load.json` 在数据包加载时依次运行 `csumc:reload` 与 `csumc_adv:reload`。

`csumc:reload` 完成以下工作：

1. 创建通用寄存器 `csumc`、`csumc2` 与常量计分板 `number`。
2. 创建死亡、击杀、生命、在线刻、放置、红石放置、挖掘、贡献产出、贡献补充、贡献消费和当前余额等目标。
3. 为六种材质的锹、镐、斧、锄分别创建 `minecraft.used` 统计目标，共 24 个挖掘来源。
4. 写入贡献换算与功能参数，启动榜单轮播和每分钟玩家循环。
5. 创建属性、兑换、技能耐久、音爆、火环和临时游戏模式等辅助目标。

`csumc_adv:reload` 创建扩展成就所需的 UUID、弓使用次数、马匹检测、树苗累计等目标。

`csumc:player_min/0` 每 60 秒以每位在线玩家为执行者调用 `player_min/1`，然后再次调度自身。`csumc:switch_scoreboard` 每 120 秒切换一次侧边栏与头顶显示。

逐刻入口 `csumc:player_tick` 目前是空函数，对应的 `player_tick.jsondisabled` 已停用，因此当前没有常驻逐刻玩家逻辑。

## 玩家统计

### 在线时间

原始值来自 `minecraft.custom:minecraft.play_time`，即游戏刻数。每分钟计算时除以 72000，得到整小时并写入 `csumc_online`。显示格式为 `<小时>h`，小数部分直接舍去。

### 挖掘量

系统并不监听方块破坏事件，而是累计 24 个工具的“使用次数”。因此它更接近指定工具的成功使用统计，且不包含徒手、剑、剪刀等方式；不同动作是否计入由原版 `minecraft.used` 统计语义决定。

### 放置量

- `csumc:placed` 进度监听任意 `minecraft:placed_block`，每次令 `csumc_placed +1` 并撤销自身，以便重复触发。
- `csumc:placed_redstone` 对 `#csumc:redstone` 标签中的方块另记 `csumc_placed_redstone +1`。

红石标签很宽，除红石元件外还包含容器、熔炉、门、玻璃、梯子、脚手架、信标等。红石类放置会同时进入总放置与红石放置，贡献计算时二者又分别折算，因此属于有意或无意的双重计数。

## 贡献值计算

每分钟重新计算总产出：

```text
贡献总产出 = floor(挖掘量 / 9000)
           + floor(普通放置量 / 1200)
           + floor(红石放置量 / 1200)
           + floor(在线游戏刻 / 72000)
           + 管理补充值

可用贡献 = 贡献总产出 - 累计消费
```

配置值全部写死在 `reload.mcfunction`：挖掘阈值 9000、放置阈值 1200、在线阈值 72000 刻、属性附加花费 6、技能附加花费 120、音爆距离 20、每次主动技能耐久消耗 20。

贡献数据只存于计分板，没有数据库、流水、幂等或跨服一致性。与当前 `design/basic/contribution-account.md` 中的正式模组账户设计是两套实现，不能直接视为等价。

## 榜单轮播

轮播顺序为在线、挖掘、放置、红石放置、击杀、死亡、贡献总产出、累计消费。每 120 秒推进一次并在 0～7 循环。侧边栏始终显示当前项目；头顶显示大多使用相同目标，但红石放置分支仍写成侧边栏，因而该轮不会更新头顶项目。

## 状态与持久化特征

- 计分板数据随世界保存，但没有流水、版本迁移与事务边界。
- `storage csumc` 只作为函数执行时的临时参数区，不承担业务持久化。
- `/reload` 会重新写入全部参数；人工修改的运行参数会被覆盖。
- 周期任务使用 `schedule function`，没有显式清理离线玩家、废弃分数或临时标签的通用流程。
