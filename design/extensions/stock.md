# 股票系统

## 市场基础

股票系统已在 `0.0.3` 实现，并在 `0.0.6` 修正界面与交易规则、`0.0.7` 调整列表布局、`0.0.8` 增加逐行操作控件、连续曲线并更正退市阈值；它依赖行业建设度系统提供的繁荣度。它使用与账户相同的数据库；单服默认嵌入式 H2，群组服使用共享 MySQL。买卖和每日核算只在服务端执行。原版客户端可以查看后备界面和交易；安装同一 JAR 的客户端可使用绘制曲线的专用界面。

- 股票在第 3 个游戏日开放。
- 每个游戏日早上 8 点更新股价，更新后的价格即为当日股价。
- 同一交易日保持 20 支股票；有空位时当天 8 点补齐。由旧版 30 支股票升级时，多出的股票在下次 8 点进入退市状态，并在当天 14 点完成退市。
- 每个行业至少有一支股票。
- 股票从内置的 36 个原版物品符号中选择，每行业 4 个候选；物品只用作股票名称和标识，交易不消耗或发放对应物品。

## 股价模型

定义：

- $p_t$：第 $t$ 个交易日的股价；
- $p_0$：上市首日的初始股价；
- $p_{\max}$：该股票允许达到的最高股价；
- $N_t$：第 $t$ 个交易日的 OU 噪声；
- $B_t$：第 $t$ 个交易日的波动基准；
- $w_t$：第 $t$ 个交易日由行业排名确定的修正参数。
- $Z_t$：每只股票独立抽取的标准正态随机数。

每支股票独立维护 OU 噪声 $N_t$ 和波动基准 $B_t$。上市时 $N_0=0$，并设长期均值为 0、时间步长为 1、$\theta=0.35$、$\sigma=0.8$。每个新交易日按下式更新噪声，状态随数据库持久化，重启后继续：

$$
N_t=(1-\theta)N_{t-1}+\sigma Z_t,\qquad Z_t\sim\mathcal N(0,1)
$$

上市时：

$$
B_0 = 0.1p_0
$$

每支股票的最高股价为其初始股价的 $10$ 倍：

$$
p_{\max}=10p_0
$$

更新股价前，使用刚刚完成的上个核算日行业繁荣度排名；繁荣度相同时按内置行业 ID 排序。

| 行业排名 | 修正参数 $w$ |
| --- | --- |
| 第 1 名 | $0.28$ |
| 第 2 名 | $0.21$ |
| 第 3 名 | $0.14$ |
| 第 4 名 | $0.07$ |
| 第 5 名 | $0.00$ |
| 第 6 名 | $-0.07$ |
| 第 7 名 | $-0.14$ |
| 第 8 名 | $-0.21$ |
| 第 9 名 | $-0.28$ |

当 $N_t>0$ 时：

$$
p_t
= \operatorname{clip}\left(
p_{t-1}+0.1N_t(1+w_t)B_{t-1},
0.3p_{t-1},
\min\left(3p_{t-1},p_{\max}\right)
\right)
$$

当 $N_t\le 0$ 时：

$$
p_t
= \operatorname{clip}\left(
p_{t-1}+0.1N_t(1-w_t)B_{t-1},
0.3p_{t-1},
\min\left(3p_{t-1},p_{\max}\right)
\right)
$$

股价使用整数，公式计算后四舍五入；下限至少为 1，上限不超过 $p_{\max}$。旧存档中已超过新上限的股票会在下一次日核算时直接裁剪至新上限。随后用 $0.1p_t$ 对波动基准执行 EMA 更新：

$$
B_t=0.9B_{t-1}+0.1(0.1p_t)
$$

波动基准和噪声以 8 位小数保存。每支股票独立抽样，不承诺某个固定随机种子；已提交的每日价格由数据库保留，不会因重启重新抽取。

## 上市

每个游戏日早上 8 点，按随机顺序从 36 个候选物品中补齐所有空位；优先覆盖当前缺失的行业。

- 如果当前股票未覆盖所有行业，必须优先从缺失行业选择物品。
- 最近退市的 5 种物品不能上市。
- 新股上市后的前 3 天不参与退市判定。

每只新股独立从闭区间 $[100,400]$ 中等概率抽取整数作为上市初始股价 $p_0$，不再按行业总建设度确定上市价：

$$
p_0\sim\operatorname{UniformInt}(100,400)
$$

## 退市

新股上市后的前 3 个游戏日不检查退市。此后，以下任一条件满足时，股票在当天进入退市状态：

- 股价降至退市阈值 $p_d=\max(0.5p_0,0.25p_h)$，其中 $p_h$ 为截至当日的历史最高股价；整数比较使用 $\max(\lfloor p_0/2\rfloor,\lfloor p_h/4\rfloor)$。结算、可选客户端界面和原版客户端后备界面共用同一个整数规则。此项自 `0.0.8` 起对尚未退市的股票生效；已经完成的历史退市不会自动撤销。
- 某行业连续 7 个游戏日繁荣度最低时，从该行业中选择“当前股价／上市股价”最低的可退市股票；该行业在触发日之后的 6 个游戏日内不会再次通过此条件触发退市。

退市流程如下：

1. 触发日 8 点标记为 `RETIRING`，不再接受买入；10:00—14:00 可以按当天正常股价手动卖出，没有随机失败率。
2. 当天 14:00 交易窗口结束时，剩余持股按当前股价的 50%（四舍五入）自动返还，不收手续费，清空持仓并标记 `DELISTED`。离线玩家也在同一数据库事务中入账；返还不计入历史总收入。
3. 余额上限导致暂不能全额入账时，余款保留，可通过 `/stock claim` 再领。若游戏时间被跳过或服务器中断，主服务器恢复后按已确定的最后股价补做结算。

令 $P$ 为退市当日股价、$Q$ 为窗口结束时剩余股数、$R$ 为应返还额，则 $R=\operatorname{round}(0.5PQ)$。实际立即入账额还受账户余额上限约束；不足部分留在返还表，不改变历史总收入。

## 交易模型

玩家直接与系统按照当日股价即时交易，不使用玩家之间的挂单撮合。

- 买入时，玩家支付的代币和手续费被销毁，并转换为持股数量。
- 卖出时，系统按照成交额扣除手续费后向玩家账户增加代币，并减少对应持股数量。
- 系统不维护可用资金池和有限股票库存，不会发生系统资金或股票不足。
- 股票没有固定总发行量。
- 市场总流通量不需要持久化或定时计算；管理统计需要时可以临时汇总玩家持股。

## 交易时间与限制

- 每个游戏日 10—14 点开放交易，对应 200 秒现实时间。
- 每个游戏日早上 8 点重置每日交易次数。
- 每名玩家对每支股票每天最多买入一次、卖出一次。
- 当日买入的股票当日不能卖出。
- 每名玩家持有同一支股票的数量不能超过 10000。
- 每次交易数量只能是 1—10000 的整数；一天对同一支股票最多成功买入一次、成功卖出一次。各服共享这项限制。
- 买入和卖出均收取 2% 手续费。

定义：

- $Q$：交易数量；
- $P$：当日股价；
- $C$：基础成交额；
- $F$：手续费；
- $C_b$：买入应付金额；
- $C_s$：卖出到账金额。

基础成交额为：

$$
C = Q \times P
$$

手续费按基础成交额的 2% 四舍五入到整数，买入应付和卖出到账分别为：

$$
F = \operatorname{round}(0.02 C)
$$

$$
C_b = C + F
$$

$$
C_s = C - F
$$

金额计算使用 64 位整数作为中间结果，但实际账户变动必须符合有符号 32 位整数范围，账户余额和历史总收入必须在 $[0,2^{31}-1]$。买入与卖出均不改变历史总收入；卖出仅增加当前余额。

交易前必须完成全部校验：

- 买入应付金额大于余额时，反馈余额不足。
- 买入后持股超过 10000 时，反馈持仓达到上限。
- 卖出数量大于当前持股时，反馈持仓不足。
- 卖出后余额超过 $2^{31}-1$ 时，反馈数值溢出。
- 主服务器市场时钟超过 5 秒未更新时，所有服务器暂停交易，避免主服务器离线后交易窗口停留在开放状态。

所有校验、账户与持仓更新、贡献值流水、股票交易流水在同一数据库事务中进行。校验失败时不改变余额或持股，也不写入流水。每笔交易生成全局唯一幂等 ID；重试必须复用原 ID，相同 ID 的不同参数会被拒绝。

## 命令与客户端界面

股票系统独立使用 `/stock`；单股股票参数可填写股票 ID、中文名称、原版物品 ID 或其不带 `minecraft:` 的路径：

```text
/stock
/stock portfolio
/stock buy <股票名称> <数量>
/stock sell <股票名称> <数量>
/stock check <股票名称> <week|month|year>
/stock retry <请求ID> <buy|sell> <股票名称> <数量>
/stock batch <buy|sell> <数量> <逗号分隔的股票ID>
/stock batch-retry <请求ID> <buy|sell> <数量> <原股票ID列表>
/stock claim
```

历史查询范围：

| 范围 | 输出规则 |
| --- | --- |
| `week` | 最近 7 个游戏日的股价 |
| `month` | 最近最多 30 个游戏日的逐日股价 |
| `year` | 最近最多 360 个游戏日的逐日股价 |

输入 `/stock` 打开股票大厅。安装同一 JAR 的 Fabric 客户端收到服务端股票快照后，显示独立的股票屏幕：列表不分页、可滚动查看全部 20 支股票；每只股票占 55 个 GUI 逻辑像素高，展示名称、行业、现价、当日涨跌值与比例、持仓、历史高低、退市阈值及当前价格与阈值之比，并绘制最近 30 个游戏日的真实股价曲线。上市日放在详情页。上涨用红色、下跌用绿色、持平用中性色。列表根据 GUI 逻辑宽度动态分列；各列使用统一的两行基线，超宽文字限制在本列内。可搜索股票名或物品 ID，直接点选多个行业、切换仅持仓；可按名称、价格、当日涨跌幅、退市阈值倍数、持仓和上市时间排序。每行有独立的“选择”与“详情”点击控件；双击行仍是打开详情的快捷方式。曲线相邻每日价格用连续且加粗的整数像素线段连接，陡峭波动时也不断线。刷新会保留市场页的搜索、筛选、排序、滚动和选股状态。

详情页提供 7/30/360 个游戏日的逐日历史股价曲线、昨收和当日涨跌、7/30/360 日相对对应旧价的涨跌值与比例（历史不足时显示缺失）、上市日与上市时长、上市价、历史最高最低、价格上限和退市阈值。若阈值落在当前图表价格范围内，则画出退市线；价格不高于阈值的 1.25 倍时显示预警。持仓部分显示数量、含买入手续费的加权平均成本、首次与最近买入游戏日、最近买入价、当前未实现盈亏和收益率，以及这支股票已卖部分的已实现盈亏。个人页可通过大厅或 `/stock portfolio` 进入，汇总账户余额、持仓市值、成本、未实现盈亏与含历史卖出及退市返还的已实现盈亏，并列出各持仓；市值与未实现盈亏按当前股价估算，尚未扣除未来卖出手续费。这些指标参照股票报价页和投资账户对账单；模组没有成交量、公司盈利或市值，因此不显示成交量、市盈率或市值。

股票行在 `0.0.8` 中注册独立的原版按钮控件，左侧单击勾选，行内单击“详情”直接打开该股票详情；它们和页面底部按钮使用相同的控件点击路径，不依赖自绘行的双击事件。行业浮层仍优先接收点击，打开时遮挡背后行的悬停与操作。列表选择框支持批量买卖。批量交易按股票逐只提交、分别校验，不保证全有或全无；请求 ID 固定，原参数重试不会重复成交。股票 ID 列表作为末尾完整命令参数解析，允许逗号分隔。客户端界面只负责展示和发起请求，服务端仍负责权限、交易与金额校验。

未安装模组的原版客户端仍可进入服务器。它通过 26.3 原生 Dialog 在一页列出全部 20 支股票，可按名称/价格排序并输入简单筛选词；详情页用逐日股价绘制 Braille 文字曲线，包含上市、区间涨跌、退市阈值和个人持仓信息，并保留买卖按钮。`/stock portfolio` 打开后备个人页。两种客户端都可使用上述文字命令。股票界面不再从 `/contribution` 首页进入。完整命令见[命令速查](../../code/docs/COMMANDS.md)。

## 数据存储

数据库迁移 V8 建立以下表，均在单服世界数据库或群组服的同一套 MySQL 中：

| 表 | 用途 |
| --- | --- |
| `stock_market_state` | 单例市场时钟、当前核算日、最后更新时间及已结算退市日；交易与每日核算先锁定此行 |
| `stock_listing` | 物品及行业、上市日、初始/当前/最高/最低价格、噪声、波动基准、退市状态及日期 |
| `stock_daily_price` | 每支股票每游戏日唯一的股价历史 |
| `stock_position` | 玩家对单股的持有数量、当日买入日和当日新增数量 |
| `stock_trade` | 股票交易、成交价、数量、手续费、全球唯一幂等 ID；玩家/股票/游戏日/方向唯一 |
| `stock_industry_streak` | 最低繁荣度连续天数和行业退市冷却日期 |
| `stock_refund` | 退市待返还额与已领取额；余额满时保留差额 |
| `stock_batch_request` | 批量交易请求 ID 与参数摘要，拒绝修改参数的重试 |
| `stock_notice` | V13 增加；按玩家、股票、游戏日和通知类型去重，保存退市预警与退款消息，供所在子服异步投递 |

每笔成交还写入 `contribution_transaction`，买入标为 `SPEND`，卖出标为 `STOCK`，退款标为 `REFUND`，来源为 `contribution:stock`；三者的 `income_delta` 均为零。V14 迁移把旧版股票流水类型改为新类型，并从账户历史总收入中剔除旧卖出流水曾计入的金额；当其他历史调整已使总收入较低时最低裁剪为零。$\theta$ 与 $\sigma$ 在本版本为代码常量，不逐股存储；日后更改参数需有版本迁移方案。

## 每日执行保障

股价核算和新股上市仍统一在主世界游戏时间早上 8 点执行；退市持股结算改在触发日 14 点执行。一个核算日从当日早上 8 点开始，到下一个游戏日早上 8 点结束。

先等上一个行业核算日结算成功，取得繁荣度，再按行业排名更新噪声和股价、处理退市、补足上市空位，最后更新共享市场时钟。交易只读取共享市场时钟，不相信子服本地时间。主服务器每约 20 tick 更新一次市场时间；共享时钟超过 5 秒没有刷新时交易暂停。

系统不依赖某一 tick 恰好为 8 点。发现未核算的游戏日时，主服务器通过 `stock_market_state` 单行锁和同一事务执行一次过渡；数据库提交后才对其他服务器可见。重启或时刻跳过后继续核算，若落后多日则逐日追赶。首次在已有世界启用时从当前游戏日开始上市，不虚构安装前的历史股价。数据库不可用时交易和核算均暂停，不生成不完整的账户或持仓记录。

持有接近退市阈值或已进入退市状态的股票时，系统为持有人写入聊天提醒；14 点自动退款时另写入退款和待领余款提醒。各子服约每 10 秒从共享数据库领取本服在线玩家的未投递通知，因此切服和离线后仍可收到。数据库通知状态与聊天发送不能组成同一原子事务，极端崩溃窗口可能造成个别提醒漏发；账户和退款金额不受影响。
