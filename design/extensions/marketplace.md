# 系统商城

当前 0.0.6 仍只实现“商店”模块；回收、拍卖和抽奖尚未实现，不作为本版的 UI 入口。商店是服务器向玩家出售原版物品，不设置系统资金或库存上限。默认商品为面包、火把和铁镐，服务端可在 `config/contribution/server.json` 的 `rewards.shopOffers` 中配置商品 ID、显示名称、物品 ID、每份数量和每份贡献值价格。单笔可购买 1—64 份，单笔物品最多 2304 个、价格最多 $2^{31}-1$。配置的物品必须存在于服务器注册表。

`/shop` 是独立入口。原版客户端使用 Minecraft 26.3 原生 Dialog 查看商品并点击购买，商品每页最多 9 种，可通过按钮或 `/shop page <页码>` 翻页；可选安装同一模组的客户端使用具有原版物品图标、搜索、价格排序、详情和数量输入的专用界面。两者发送的都是服务端命令，客户端显示价格不构成成交依据。购买前以数据库账户行锁检查余额；不足时返回“余额不足”，不扣款、不创建订单或流水。成功时在同一事务内扣款、写 `SHOP_BUY` 流水、创建 `shop_order` 订单和 `reward_delivery` 待发物品记录。购买不会改变历史总收入。

每笔订单有全局唯一订单 ID。结果不明时用 `/shop retry <订单ID> <商品ID> <份数>` 沿用原 ID 和参数；已提交的订单只返回原订单，不重复扣费或交付。订单 ID 不允许换商品、数量或玩家使用。物品领取队列支持断线、背包已满和跨服后继续领取；背包放不下的剩余物品会掉落在玩家附近。领取时数据库短租约防止多服同时领取同一件待发物品；租约过期后可恢复。游戏背包与 SQL 数据库不能加入同一个原子事务，因此服务器恰好在“物品已进入背包但交付确认未写入数据库”之间崩溃时，恢复后存在重复交付的极小窗口；管理员可用订单和待发物品表核查。这里优先避免已扣费却永久丢失商品，不能将它误称为严格一次交付。

群组服主服务器发布奖励配置指纹到共享数据库，商店购买和签到、建设度发放都会比对指纹；各服配置不一致时拒绝相关经济操作，防止价格和奖励跨服分叉。修改奖励或商店配置后，应同步各服配置并重启。该指纹不影响已经存在的待领取物品。
