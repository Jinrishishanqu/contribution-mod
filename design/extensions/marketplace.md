# 系统商城

当前 0.1.3 实现系统商店；回收、拍卖、抽奖尚未实现。服务器出售物品，没有系统资金或库存上限。`/shop` 独立打开商店，原版客户端可以进服并通过 Dialog 购买；安装同一模组的客户端使用专用商店。`/shop ui_vanilla` 强制调试原版界面，本次导航中的管理、编辑和返回均保持原版模式。

## 商品与管理

商品统一保存在数据库的 `shop_offer` 中，群组服共享同一个目录。每件商品自动分配稳定、不可复用的正整数编号。商品字段包括名称、物品 ID、每份数量、售价、描述、上架状态、排序值和编辑版本。名称最多 64 字，描述最多 512 字，每份 1—64 个物品，售价 1—2147483647 贡献值。物品必须存在于服务器注册表。排序值越小越靠前，相同排序值按编号排列。当前最多保留 256 件商品（包含下架商品），以约束快照大小、查询和客户端筛选开销。

主服务器第一次升级或创建数据库时，自动从 `rewards.shopOffers` 导入初始商品，并保留旧字符串 ID（如 `bread`、`torch`）作为购买与旧订单重试的兼容别名。默认导入面包、火把、铁镐。导入只进行一次；之后重启、修改配置文件都不会覆盖目录，应通过管理界面或命令修改。下架不会删除商品、历史订单或待发物品，管理员可再次上架。

OP 等级 2 的玩家可点击商店右上角“管理”，或执行 `/shop admin`。管理目录显示已上架及已下架商品，选中后点击“编辑商品”；“新建商品”打开完整表单。表单可修改名称、物品 ID、数量、价格、排序、描述及上架状态。客户端表单支持重新读取；保存时校验编辑版本，其他管理员已经修改时拒绝覆盖，并保留输入供修改或重读。原版 Dialog 同样提供新建、编辑及“保存并上架／保存并下架”；原版表单通过命令模板提交，名称和描述不要含双引号、反斜杠，复杂文字可用正确转义的管理员命令填写。

管理员命令：

```text
/shop put_on <物品ID> <名称> <每份数量> <售价> [描述]
/shop take_off <商品编号>
/shop modify <商品编号> [名称] [每份数量] [售价] [描述]
```

`put_on` 自动分配编号并上架，排序默认 0。`take_off` 只下架，不删除记录。`modify` 按名称、数量、售价、描述的顺序填写；只修改后面的字段时，前面填 `-` 保持不变，未填写的尾部字段不变；描述填 `""` 清空。例如 `/shop modify 4 - - 35` 只修改售价；省略全部修改字段则打开编辑页。中文名称或含空格的名称用引号；描述可直接填写多个词。物品、状态和排序可在完整管理表单中修改。

## 两套界面

专用客户端面板最大宽度为 460 GUI 逻辑像素，左侧使用两列商品卡片，搜索框与目录共用边界。卡片作为真实控件注册，而不是仅绘制命中区域；点击切换选中商品，同时更新右侧名称、编号、物品、数量、价格与文字描述。刷新与关闭位于右上角，背包溢出提示位于底部领取按钮左侧。目录可滚轮滚动，并显示只读滚动条，不提供拖动。搜索支持名称、物品 ID、商品编号，可选择商品配置顺序、名称或价格排序。刷新和购买后的自动刷新保留搜索、排序、选中商品、份数和滚动位置；退出后重新 `/shop` 打开重置。

管理员目录复用同一双列选择布局，另外使用独立编辑页，返回时重新建立控件，不复用旧按钮坐标。操作失败在专用界面显示提示，同时发送聊天反馈。专用页面不暂停单人世界。

原版 Dialog 每页最多 8 件商品，显示编号、数量、售价及描述，可直接购买一份、分页、刷新、领取待发物品。购买更多用 `/shop buy <编号> <份数>`。管理员入口及表单不需要客户端模组。

## 交易与交付

购买使用共享数据库的当前商品记录。商品行锁保证与编辑同步，客户端界面附带商品版本；目录过期时拒绝成交并提示刷新，不按玩家没看到的新价格扣款。文字命令省略版本时，以服务器当时的商品价格成交。余额不足或商品已下架时不扣款、不创建订单或流水。单笔 1—64 份，最多 2304 个物品，总价不超过 $2^{31}-1$。

成功时在同一事务中锁账户、扣款、写 `SHOP_BUY` 流水、创建 `shop_order` 和 `reward_delivery`。购买不影响历史总收入。订单有全局唯一 ID；结果不明时 `/shop retry <订单ID> <商品ID> <份数>` 沿用原请求。即使之后商品改价或下架，已提交订单仍返回原结果，不重复扣款或创建待发记录。换玩家、商品或份数使用同一订单 ID 会拒绝。

待发物品队列支持断线、背包已满和跨服后领取，背包放不下的剩余物品掉落在玩家附近。数据库短租约避免多服同时交付同一待发项；游戏背包与 SQL 不能加入同一原子事务，服务器在物品已进入背包但确认未入库时崩溃，仍存在重复交付的极小窗口。这不是严格一次交付。

商品目录不再纳入奖励配置指纹，因为价格与商品以共享数据库为准。签到、建设度奖励和时区等奖励配置仍校验主服务器发布的指纹，各服须一致；购买仍要求奖励配置校验通过。升级时群组服所有节点应更新到同一版本，由主服执行 V17 数据迁移并初始化目录。先停服备份数据库，再升级。

## 性能

目录、编辑、购买都在现有有界数据库线程池中执行，不阻塞游戏主线程。服务器仅在玩家请求时读取商品快照；客户端搜索或排序变化时重建缓存，不逐帧访问数据库或重新排序。每页只注册当前容量的卡片控件，滚动复用这些控件。坏天鹅选择与每日结算也在市场后台事务中完成，与商店绘制无关。
