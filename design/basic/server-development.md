# 服务器建设度统计

> 当前实现基线：0.2.4。完整指令与权限以[离线 Wiki](../../documentation/wiki.html)和[指令表](../../documentation/commands.xlsx)为准；功能变更须同步代码、本文及统一文档源。

## 范围与行业

行业建设度用于统计服务器中的有效游玩、建设和生产行为。繁荣度是本系统的派生指标，股票等拓展功能读取繁荣度，不反向参与建设度统计。

当前版本 只实现以下九个内置行业，不提供新增、删除、自定义行业的配置接口。玩家可以通过原版图形界面查看行业数据，详见[图形界面](graphical-interface.md)。

| 行业 | 稳定路径 |
| --- | --- |
| 土建园林 | `construction_landscaping` |
| 采矿冶金 | `mining_metallurgy` |
| 能源化工 | `energy_chemical` |
| 加工制造 | `processing_manufacturing` |
| 科技魔法 | `technology_magic` |
| 农林牧渔 | `agriculture_forestry_livestock_fishery` |
| 军工食药 | `military_food_medicine` |
| 流通服务 | `circulation_services` |
| 文教民生 | `culture_education_livelihood` |

行业 ID 为 `contribution:<稳定路径>`，历史数据以 ID 为键，不以中文名称为键。每个行业维护当日建设度、已结算总建设度、长期 EMA、近期 EMA 和繁荣度。

## 建设度贡献值发放

当前实现还按个人九行业累计建设度定期发放贡献值。令 $D_i$ 为玩家在行业 $i$ 的累计建设度，$w_i$ 为配置权重，$E$ 为应发放总量，$P$ 为该玩家已经从建设度获得的贡献值：

$$
E=\left\lfloor\sum_{i=1}^{9} w_iD_i\right\rfloor,\qquad G=\max(0,E-P)
$$

九个默认权重均为 $1/250$，配置在 `rewards.developmentWeights`，默认每300秒扫描一次。只有九项仍统一为旧默认1/1000或1/10000的完整配置自动升级，混合和自定义权重不改写。新权重用于现有个人累计建设度的应发公式，扣除已经发放的金额，不重算或追回历史奖励。主服务器独占扫描，后台按UUID每页32人处理。只有 $G>0$ 才发放；余额、历史总收入、已发累计及DEVELOP流水同事务更新，上限未能发出的应发量保留。无主机器只增加服务器建设度，不产生个人奖励。

配置 `statisticsServers` 指定允许采集的服务器 ID，默认只有 `survival`。其他服务器不采集统计。群组服所有服务器连接同一个 MySQL 数据库，生存服始终是唯一主服务器；单服使用世界内嵌入式数据库。玩家行业建设度仅接受生存或冒险模式；原始放置、挖掘次数也记录创造模式的成功操作。没有明确玩家主体的机器生产只增加服务器建设度，不猜测机器所有者。

## 核算日与结算

主服务器以主世界游戏时钟划分核算日。令 $T$ 为世界时钟 tick，$d$ 为核算日：

$$
d=\max\left(0,\left\lfloor\frac{T-2000}{24000}\right\rfloor\right)
$$

正常核算区间为每天 8:00 至次日 8:00。游戏内睡眠跳时不会错过 8:00 边界；首次安装所在的区间视为不完整日，建设度和累计总量照常保留，但不用于 EMA 初始化。安装前的历史游戏日不补造零值记录。

主服务器到达新核算日后发布该日规则。其他统计服务器每 100 tick 查询一次主服发布的核算日，不使用各自世界时间决定日期。规则哈希不变时，日期推进不等待全部缓冲清空；批次仍保留原日期。真正的规则变更必须先完整排空，再切换。跨服观察切日存在最多约 5 秒加数据库延迟的同步窗口。旧日关账只等待该日及更早日期的建设度和移动批次确认提交，当天持续活动不阻塞旧日关账；在途旧日批次仍会阻塞。主服必须等待所有指定统计服务器确认旧日提交完毕，才结算旧日。未在线或未恢复的统计服务器会阻止结算，不被当作零建设度。

正常结算从 8 点开始，失败重试与历史追赶只在 8:00—18:00 的安全窗口运行；日常事件采集不受这个时间窗口限制。

结算按日顺序追赶，以任务表唯一键和行锁保证重复启动不会重算。一日内九个行业的每日快照、总量、EMA、繁荣度与任务成功状态在同一事务中提交。新日累加器按首次事件懒创建，缺失记录在查询及结算时等价于零。主服时间倒退到数据库已记录日期之前时暂停规则切换，不能覆盖已结算历史。

定义 $n$ 为有效数量，$u$ 为单位建设度，$\Delta D_d$ 为本次增量：

$$
\Delta D_d=nu
$$

不设置每日建设度上限。累计值采用 $0$ 至 $2^{63}-1$ 的非负整数；达到存储上限时饱和于最大值，不回绕、不取消已经成功的游戏操作。

## 繁荣度

定义：

- $x_t$：第 $t$ 个完整核算日的行业建设度；
- $L_t$：长期日建设度 EMA；
- $R_t$：近期日建设度 EMA；
- $P_t$：繁荣度。

第一个完整日只保存建设度，EMA 为 `NULL`，繁荣度显示为 0。第二个完整日结束后初始化：

$$
L_2=R_2=\frac{x_1+x_2}{2}
$$

两日均为 0 时也正常初始化。自第三个完整日起：

$$
L_t=0.99L_{t-1}+0.01x_t
$$

$$
R_t=0.8R_{t-1}+0.2x_t
$$

先更新 EMA，再计算繁荣度：

$$
P_t=0.7\frac{R_t-L_t}{L_t+1}+0.3\frac{x_t-L_t}{L_t+1}
$$

初始化后两日均为零时繁荣度为0，稳定建设满足 $x_t=R_t=L_t$ 时也为0。分母加一只避免除零，不在分子添加负偏移；建设相对长期基准减少仍为负。任一完整日的零值都参与后续计算。数据库使用 `DECIMAL(30,8)`，Java 使用 `BigDecimal`，中间 EMA 和除法以 8 位小数四舍五入。

## 玩家标签

九个行业分别使用以下标签，同一种动作下一个对象最多对应一个行业，重复配置导致整份候选规则被拒绝。

| 标签 | 注册表 | 有效计数 |
| --- | --- | --- |
| `craft_<行业>.json` | 物品 | 背包、工作台实际转移到玩家的合成产物数量，包括 Shift 点击与快捷交换 |
| `place_<行业>.json` | 方块 | 玩家成功放置操作，每次 1 |
| `mine_<行业>.json` | 方块 | 玩家成功挖掘操作，每次 1 |
| `use_<行业>.json` | 物品 | 完成食用、饮用的实际消耗数量；耐久损失不计行业分数 |
| `interact_<行业>.json` | 方块 | 服务端交互后方块状态改变或手持物品数量减少，每次 1 |

前 27 个 craft/place/mine 标签只统计玩家直接操作，不用于自动合成器、机器、爆炸或环境变化。use/interact 另有 18 个标签，空标签合法。use标签保留既有食物、饮品、武器、防具、采掘工具、农具等定义；本轮只删除耐久损失采集，工具和装备条目不清理，当前仅食用/饮用完成的消耗路径可形成use计分；默认方块交互来源包含堆肥桶、浆果、蜂巢、耕作地表、炼药锅、音符盒及唱片机等。是否真正产生计数还必须满足上述结果检查，打开界面不计数。

同一动作不设置优先级覆盖；需要改变行业时应从旧标签删除，再加入新标签。place/mine 按实际方块 ID 匹配，不按物品 ID 匹配；火把与墙上火把等不同方块类型分别列入。完整注册项见资源中的 `all_items.json`、`all_blocks.json`，物品与实际放置方块的一对多关系见 `placement_map.json`。

可逆合成排除表对应的 37 个物品禁止写入 craft 标签，启动和重载均校验。运行时排除清单为 `data/contribution/contribution/reversible_craft_exclusions.json`；中文审核表见[可逆合成排除表](../definitions/可逆合成排除表.csv)。生产设备不借用 craft 标签。

对象标签按四份人工XLSX同步，craft1065、place1206、mine1129。合成每玩家每行业累计64个实际产物计1点，同业不同物品可累加，余量跨日、重启、跨服保留，不扩展到放置或挖掘。Shift按真实转移数量，不按点击数。方块交互排除BlockItem以及已有主事件覆盖的锅/清洗、骨粉、蜂蜜、骨粉提取等成功结果，避免重复计分。use标签本身不能让未接入的瞬时使用行为生效。

## 游戏事件映射

[中文游戏事件 → 行业映射表](../definitions/游戏事件-行业映射表.csv)用于人工定义，运行代码读取 `data/contribution/contribution/game_event_industry_map.json`。每个事件唯一映射到一个内置行业，一个行业可接收多个事件。

默认物品产出、实体或成功动作每单位1点；八种交通每10格1点，合成每64产物1点。已适配事件支持正整数unit_size和非负unit_value，原始数量与余量在统计事务统一折算，逐调用不截掉小批数量；unit_value=0只记录观察量。事件ID与计量类型仍须对应已有完成适配器，不能只增加JSON宣称新行为生效。88项主表的接入和待接入状态见[实施进度](industry-definition-rollout.md)。

| 来源 | 完成时机与归属 |
| --- | --- |
| 熔炉、高炉、烟熏炉 | 输出槽实际增加产物后；独立产物标签区分矿物、化工、建筑材料和食物，只增加服务器建设度 |
| 合成器 | 配方成功生成产物后，默认加工制造，只增加服务器建设度 |
| 繁殖、驯服、治愈 | 成功完成动作，能明确关联玩家时同时增加个人与服务器建设度 |
| 剪毛、挤奶、钓鱼 | 实际产物生成；不以普通拾取作为来源 |
| 生物击杀 | 生存或冒险玩家完成任意LivingEntity击杀；环境死亡不计，旧kill_hostile键只为历史兼容保留 |
| 村民交易 | 输入扣除、交易完成后计一次，不按打开界面或选择条目计数 |
| 锻造、铁砧、附魔、酿造 | 成功取出修改结果、附魔成功或酿造完成；没有明确玩家的自动生产只计服务器 |
| 交通距离 | 鞘翅、马、船、矿车、猪、炽足兽、快乐恶魂、鹦鹉螺八类有效移动 |

熔炉产物使用独立的 `process_furnace_mineral/chemical/material/food` 物品标签，生产时分类，不在取出时重复计数。不同类别的产物不能重复归类。

玩家普通步行、在线时长、普通拾取、自然生长、无产出机器空转、容器存取和原始右键均不采集。容器放入、取出操作不缓存、不落库，不属于流通服务来源。

## 交通距离

移动适配器复用原版服务端的移动统计增量，校验玩家实际处于对应滑翔或乘坐状态，不扫描世界实体。单次增量超过 16 格时作为异常跳变丢弃，创造和旁观模式不计。

厘米增量转换为百万分之一格的整数进入批次。按“玩家 UUID + 移动方式”保存余数，跨日、离线、重启和跨服继续累计；数据库事务对余数行加锁，将余数更新、服务器建设度、个人行业建设度和批次幂等标记一起提交。重载改变距离单位后，尚未折算的真实距离按新单位换算，不清空余数。

## 方块操作与交互去重

一次放置、挖掘无论影响多少方块位置都按一次操作统计，门和床等不会按部件数量累计。原始玩家放置、挖掘次数不受以下短时去重影响；行业建设度受影响。

令去重键为：

$$
K=(s,d,u,a,x,y,z,b)
$$

其中 $s$ 为子服，$d$ 为维度，$u$ 为玩家 UUID，$a$ 为放置、挖掘或交互，$(x,y,z)$ 为本次玩家操作的目标锚点，$b$ 为方块注册 ID。不比较朝向、开关、含水等方块状态。不同动作独立去重，多方块操作只报一个锚点事件。

若 $t$ 为当前 tick、$t_K$ 为同键上次成功操作 tick，则只有首次出现或满足下式才增加行业建设度：

$$
t-t_K\ge20
$$

被去重的操作仍更新上次观察时间，所以连续快速往返操作不会每秒自动获得一次分数。交互还必须先通过结果检查。服务器与个人行业累计使用同一个去重结果。缓存只在本服内存保留，每 20 tick 清理过期项，重启不恢复一秒内的缓存。

## 热重载与持久化

主服执行原版 `/reload` 后解析标签和事件映射，构造不可变的成员快照。跨行业重复对象、未知行业、非法事件、非正整数和可逆 craft 产物均拒绝整份候选配置，旧配置继续生效。成功候选在下一游戏日 8 点发布；重载不会立刻改变当日行业匹配。

数据库的 `contribution_rule_snapshot` 按 SHA-256 保存去重后的规则 JSON；`contribution_rule_epoch` 保存核算日到规则哈希的对应关系。子服直接使用主服发布的规则快照，不按自己的数据包私自改变行业规则。启动时加载历史快照，保证旧统计日志仍按原规则重放。当前 `config_version=1` 表示规则结构版本，具体业务规则身份以 `config_hash` 和核算日为准，不用结构版本区分每次重载。

高频事件先聚合，默认 100 tick 或 500 个脏键触发批次。批次持久化与容量保护见[运行时架构](../infrastructure/runtime-architecture.md)。单个批次内的原始操作、个人建设度、服务器建设度、距离余数和幂等标记处于同一个数据库事务；群组服由 InnoDB 承担。

| 数据表 | 用途 |
| --- | --- |
| `industry_day_accumulator` | 行业当日累加器，是当日建设度唯一权威来源 |
| `industry_daily` | 已结算日的九行业快照 |
| `industry_state` | 总建设度、最后结算日、EMA 和繁荣度 |
| `player_activity_stats` | 玩家原始放置、挖掘次数 |
| `player_industry_stats` | 玩家各行业累计建设度 |
| `player_distance_remainder` | 各移动方式的未折算距离 |
| `measurement_remainder` | 玩家/事件或来源服/机器事件的实际产物单位余量 |
| `event_activity_day` | 按来源服/核算日/可靠主体/事件聚合的原始完成数量 |
| `statistics_batch` | 批次身份及内容哈希 |
| `statistics_day_close` | 每台统计服务器的关日确认 |
| `scheduled_task_run` | 主服结算的幂等任务、租约和状态 |

Fabric 完成事件优先；缺少对应事件时使用窄范围服务端 Mixin。适配器只上报已完成行为，行业分类、数量换算、去重、批量持久化和结算分别在独立组件处理。

## 游戏事件设计审核与参与度解释（实施前记录，2026-10-04）

以下段落为0.1.13实施前的审查记录，不表示当前仍按16格或每个合成产物1点计数。最新覆盖见[实施进度](industry-definition-rollout.md)，原XLSX保留以免覆盖人工批注。

游戏事件人工审核表已区分现行实现与目标提案。当前总服务器建设度含无主设备产出；玩家群体参与宜汇总有效个人事件并与无主产出并列展示，不能直接把服务器总量当作所有玩家的个人参与之和。自然生态、循环物流与空载机械动作仅列为观测候选，尚未接入；未来设施归属必须采用显式登记与生命周期规则，不根据附近玩家或最后点击者猜测。

事件审核表的10格移动、64产物合成及恢复量/燃料累计是设计目标，不改写本文件现行16格、标签单位1的规则。未实现累计余数的来源不能直接设置较大unit_size，现有普通gameEvent逐调用取整会丢失小批数量。候选适配器须以26.3实际完成结果验证，同一动作不能同时计通用标签、专用事件、原版统计和进度。

审核发现当前普通熔炉矿冶产物标签包含石头、玻璃等材料，而人工目标按加工制造归类；当前普通村民交易适配器不覆盖流浪商人，TamableAnimal驯服适配器不保证马科覆盖。以主表现行范围列和实际代码为准，待后续实施任务解决；此次不改变已有规则及历史数据。

事件定义表本轮将同次完成结果限定为一个主积分入口。标签总入口及语义子类从事件主表移除，由各自标签定义承担；附属恢复/效果观测附加建设度为0，专用交互应替换对应通用入口，工具耐久不叠加同次主结果。本轮目标改为单次完成入口与互斥分支，不再要求跨钩子完成标识或实体/设施生命周期表；现有20tick方块去重保持。详见事件表主来源、身份、互斥、单点方式与可接受误差列。

事件判定优先低开销：只在原版单次完成点读取当次成功结果、参数或原版已有主体。允许调用内临时前后值，不新增轮询、连续事件窗口、设备历史或轨迹缓存。缺少可靠主体只记服务器。燃料/蜂蜜/海龟等可按动作计，信标重复重新激活允许计数；代价列在人工表中。触发立即记录原始量，经济阈值属于普通汇总结算，不作为触发条件。本轮未修改运行计分代码，也未进行性能压测。

## 2026-10-04 取消通用耐久行业计分

按用户要求，ItemUseCompletionMixin不再注入hurtAndBreak，工具、武器、防具及其他物品的实际耐久损失不再通过usedItem累计行业建设度。原版耐久损耗与特殊装备耐久机制保持；finishUsingItem食用、饮用完成的实际消耗计分及特殊物品消费保持。use/interact标签JSON、事件工作簿和其他人工定义表均保持原有内容，不删除工具、装备标签成员，不新增事件或交互定义表。既有专用事件仍独立使用GameEventRules，取消耐久来源不等于删除物品使用规则或取消其他来源计分。
