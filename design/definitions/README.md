# 中文行业定义表

本目录只用于玩法设计和人工审核，不由模组运行时代码读取。

- [游戏事件 → 行业映射表](游戏事件-行业映射表.csv)
- [玩家合成物品 → 行业定义表](玩家合成物品-行业定义表.csv)
- [玩家放置方块 → 行业定义表](玩家放置方块-行业定义表.csv)
- [玩家挖掘方块 → 行业定义表](玩家挖掘方块-行业定义表.csv)
- [可逆合成排除表](可逆合成排除表.csv)

合成、放置和挖掘表分别用于审核玩家手动合成产物、实际生成的方块及资源采集方块的行业归属，对应 `code/src/main/resources/data/contribution/tags` 下的 27 个 JSON。行业没有数据行即表示当前无定义。游戏事件表用于审核事件的行业和单位建设度，不由代码读取。可逆合成排除表列出的物品不计入合成建设度。

CSV 使用 UTF-8 BOM，方便 Windows 表格软件直接打开。中文名称来自 Minecraft 26.3 官方简体中文语言文件，注册 ID 是跨语言和运行时配置使用的稳定标识。

`minecraft:bee_nest` 和 `minecraft:beehive` 的放置归属统一为“农林牧渔”，运行时 JSON 与生成规则已同步到中文表定义。

重新生成命令由 `code/tools/generate_chinese_design_tables.py` 提供，以运行时 JSON 为源生成 CSV。修改玩法定义后应同步更新 JSON 与表格，并重新运行互斥检查。18 个 use/interact 标签是独立来源，不改变这 27 个玩家合成、放置、挖掘标签的用途。

## 2026-10-04 游戏事件映射审核

游戏事件 XLSX 与 CSV 已同步为人工审核主表。主表保留88条记录；以用户最新保存版本为基线，移除13项通用标签入口、细分项与重复击杀子类，不恢复用户删项。原表存档和既有追溯保留。新增当前/目标行业、单位、覆盖范围、稳定行业ID、归属与去重约束，避免将拟议规则写成已实现功能。

个人参与、玩家群体参与、无主设备生产、自然生态活动须分别解释。当前个人事件同时累计个人与服务器建设度，无主设备只累计服务器；因此服务器建设度不等于所有玩家参与程度之和。自然生长、循环搬运、反复伸缩等可以映射行业作为活动观测，不能据此自动归属个人或直接给予贡献奖励。

10格交通仍为目标提案；用户已确认合成统一每64个实际产物计一次，尚未应用运行代码；恢复量改为单次有效增量观测；燃料改为每次实际扣除一份的成功动作，不再换算热量或追踪燃烧时长；现行六类交通每16格1点，标签合成每个产物1点。除距离外的累计余数及新计量类型尚未实现。当前注册25个运行时事件；表中保留24个同名ID，任意生物击杀条目注明现行kill_hostile与扩展目标的替代关系。新增审核键不表示已注册事件，不能只增加JSON配置就启用。

原文件的长产物列表不是现有标签覆盖证明：当前熔炉矿冶标签包含石头、玻璃等材料；目标分类与当前范围在表内分别记录。当前驯服仅覆盖TamableAnimal，村民交易仅覆盖普通村民；这些实现缺口需后续独立修复。此次审核不修改标签、事件规则、经济权重和历史数据。

`generate_chinese_design_tables.py`生成的是运行时基础快照，不能保留本次人工提案、批注和追溯；勿对人工审核表运行默认覆盖。需要快照时应指定独立临时输出目录，并人工比较合并。

## 三份对象定义表 GPT 建议审核（2026-10-04）

三份XLSX曾添加逐项GPT建议，覆盖放置1206、合成1065、挖掘1263个对象。三份主表现均按用户确认的B列整理为A—E五列纯映射，原表存档保持。运行时标签尚未按这些人工定义调整。

审核基于本地26.3原版配方、项目内置配方、注册目录、placement_map、37项可逆合成排除和当前27个craft/place/mine标签。建议区分行业取舍、真实手动配方或特殊修复来源、方块形成路径、多部件计量、作物成熟条件、原行业与JSON文件不一致及候选/生效差异。ID存在不等于可手动合成或直接放置；同一对象在不同动作中可合理分属不同行业。

合成标签当前运行行为仍按产物个数每个1点；人工表已确认统一每64个产物计一次，不是64次点击或配方执行，尚未同步运行实现；砂轮主要处理装备而非采矿，漏斗物流功能不因红石控制能力而必须归科技。建筑拆除也是土建参与，可保留行业活动度，但贡献奖励应另区分净建设和可回收循环；20tick去重不证明对象天然生成，不防慢速循环。

当前标签成员总数为craft1008、place1169、mine266。人工表覆盖之外仍有38个现行place标签ID；本轮不以这些运行时差异覆盖用户审核后的B列，旧GPT说明随主表清理移除；其中技术/创造对象不自动建议加入收益。部分合成条目仅有冶炼/锻造等来源，另有特殊手动修复可产生旧装备，不能一概称为可手动制造。DS的行业条目数量或“缺失”旧描述不构成实施指令，所有建议需后续明确取舍后再同步代码。

## 同次完成结果去重（2026-10-04）

事件XLSX与CSV同步新增主计分来源、计分身份、互斥规则、单点采集与去重方式、可接受的判定误差。主表不再列出通用合成、放置、挖掘总入口及其已有细分项。播种、蘑菇种植、可可种植/收获和农作物挖掘由对象定义表的place/mine承担；右键浆果、唱片机、音符盒由interact规则承担，不列作独立事件。袭击队长击杀由击杀主规则承担。主表保留独立完成结果、互斥分支和21项不附加建设度的活动观测。铁砧、骨粉提取、蜂蜜收获、锅清洗、实体击杀和引雷等按同次结果选择唯一主入口，不叠加通用交互、工具耐久、原版统计或进度。食物恢复、生命恢复与状态效果只记录附属量。不同生产阶段仍可分别记录。

每个成功结果只选择一个完成入口，冲突通用规则直接排除，不建立跨钩子序号或历史去重表。个人事件只记个人一次，玩家总和由个人派生，世界活动另列。本轮只改人工定义，不改变运行时行为。

## 单次事件与低开销判定

触发只使用一个原版完成分支的当次参数、成功结果或原版已有字段，允许同一次调用内短时前后比较。模组不新增轮询、时间窗口、连续事件关联、轨迹、植株轮次、设施生命周期、历史最高等级或UUID历史表。原版自身的繁殖/治疗/刷取过程不由模组重复追踪，直接在最终完成点读取已有结果。

燃料扣除、蜂蜜收获、海龟产卵/孵化按成功动作计。信标只在单次更新内从未激活变激活时记录，接受关闭后再激活重新计数，不保存历史最高等级。没有当次可靠玩家则只记服务器。距离直接读原版当次统计增量，不新建位置采样任务。计数与权重汇总仍可累计原始量，汇总不构成事件触发前置条件。表中单点方式与可接受误差列明确这些取舍，性能尚未实测。
