公共接口

公共接口供其他 Fabric 模组在逻辑服务端提交贡献值变更，余额变更通过异步请求执行。

  1. 入口与依赖
  2. 请求字段
  3. 调用示例与线程
  4. 返回状态
  5. 幂等与重试
  6. 调用约束

入口与依赖

  • 模组通过 cn.contribution.api 包提供稳定的公共接口。其他模组只能依赖该包，不应直接访问账户仓库、数据库连接、流水服务或其他内部实现。
  • 公共入口为 ContributionApi；接口只能在逻辑服务端调用。
  • 贡献值模组尚未发布到 Maven 仓库时，可以把开发模组文件放进调用模组的 libs 目录并用 compileOnly 引用。
  • 接口不分别提供 add 和 remove 函数：所有余额变更统一通过 changeBalance 提交，使数值校验、余额检查、历史总收入更新、幂等检查和流水写入无法被调用方绕过。
CompletableFuture<BalanceChangeResult> changeBalance(
        BalanceChangeRequest request
);

请求字段

字段类型说明
idempotencyIdUUID调用方为一次业务操作生成的全局唯一幂等标识符
targetAccountTarget通过玩家唯一标识符或玩家名称指定的单个账户；接口不接受目标选择器
amountint带符号的余额变动量；正数增加，负数减少，不能为 0
typeBalanceChangeType目前支持 EXTERNAL 与 REFUND
sourceIdentifier调用来源，例如 quest_mod:quest_reward；字符串形式最多 128 个字符
reasonString流水原因，最多 64 个字符
noteString可选备注，最多 64 个字符
affectTotalIncomeboolean是否将带符号的 amount 同步作用于历史总收入；退款必须为 false

EXTERNAL 允许正向或负向变动。旧的七参数构造器保留原默认规则：正向 EXTERNAL 计入历史总收入，负向 EXTERNAL 不影响历史总收入；新的八参数构造器可明确传入 affectTotalIncome。REFUND 的 amount 必须为正数，且 affectTotalIncome 必须为 false。

调用示例与线程

  • changeBalance 异步执行数据库操作。调用方不得在服务器主线程使用 join()、get() 或其他阻塞方式等待结果。
  • CompletableFuture 的完成回调不保证位于服务器线程；需要修改世界、访问实体或向玩家发送消息时，必须通过 MinecraftServer.execute 返回服务器线程。
  • 客户端界面需要修改余额时，必须先向服务端发送经过校验的请求，再由服务端调用接口。
ContributionApi.getInstance()
        .changeBalance(request)
        .thenAccept(result -> {
            server.execute(() -> {
                if (result.successful()) {
                    // 使用 result.balanceAfter() 反馈余额
                } else {
                    // 使用 result.message() 反馈失败原因
                }
            });
        });

返回状态

状态含义
SUCCESS操作成功，或幂等重试取得了原成功结果
ACCOUNT_NOT_FOUND玩家名称或唯一标识符对应的账户不存在
INVALID_AMOUNT数量为 0、超出范围，或不符合操作类型要求
INVALID_TEXT原因、备注或来源标识不符合要求
INSUFFICIENT_BALANCE扣款后余额将小于 0，或历史总收入将小于 0（反馈「历史总收入不足」）
BALANCE_OVERFLOW操作后的余额或历史总收入将超过 231-1
DATABASE_UNAVAILABLE数据服务不可用或结果暂时无法确认；必须沿用原幂等标识符重试
IN_PROGRESS为兼容保留；当前实现不会主动返回该状态
IDEMPOTENCY_CONFLICT相同幂等标识符被用于内容不同的请求

参数错误、余额或历史总收入不足等可预期的业务失败通过 BalanceChangeResult 返回，不使用异常表示。结果中的可选数值使用 OptionalInt，流水标识符使用 Optional<UUID>，不使用 0 或负数作为缺失值。兼容版本可以增加新的结果状态，因此调用方处理状态时必须保留未知状态分支。

幂等与重试

  1. 创建并持久化业务记录与幂等标识符。
  2. 构造不可变的 BalanceChangeRequest。
  3. 调用 changeBalance，不阻塞服务器主线程。
  4. 检查 BalanceChangeStatus。
  5. 仅在 SUCCESS 之后执行依赖余额变更成功的后续操作。
  6. IN_PROGRESS、超时或 DATABASE_UNAVAILABLE 后，使用原请求重试。
  7. 业务失败时保留原结果，不使用新幂等标识符暗中重做同一操作。
✖
不要在重试时生成新唯一标识符每次重试都调用 UUID.randomUUID() 会让系统把每次尝试视为新交易，造成重复发放或重复扣款。幂等重试取得原成功结果时状态仍为 SUCCESS，同时 replayed() 返回 true。

调用约束

Java 模组接口的调用方与贡献值模组运行在同一个 Java 虚拟机中，属于服务器管理员主动安装的受信任代码。source 用于审计、统计、日志和可选的来源白名单，不作为无法伪造的安全身份凭证。接口仍会独立执行全部参数、数值和余额校验。

其他模组不得：

  • 直接修改账户表或流水表；
  • 获取并长期持有数据库连接；
  • 绕过余额上下限或单次数量范围；
  • 自行计算变动前后余额；
  • 自行生成流水标识符；
  • 从客户端直接调用余额变更；
  • 把 IDEMPOTENCY_CONFLICT 当作普通网络错误重试。

公共接口遵循语义化版本：cn.contribution.api 中的类型在同一主版本内保持源代码与二进制兼容；删除类型、修改函数签名或改变既有状态语义时必须增加主版本。
