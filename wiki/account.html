贡献值账户

贡献值账户保存玩家的余额、历史总收入和交易流水，以玩家唯一标识符区分身份。

  1. 账户身份
  2. 收入与支出
  3. 查询余额与流水
  4. 排行榜
  5. 数值规则
  6. 操作结果
  7. 管理与数据

账户身份

玩家首次进入服务器时自动创建账户，初始余额和历史总收入均为 0。账户以唯一标识符区分身份，玩家名称用于查找和显示。

  • 名称以 bot_ 开头的假人不建立账户；前缀匹配忽略大小写。
  • 查询和管理支持在线或离线玩家的名称、唯一标识符。
  • 玩家选择器用于单账户操作时须恰好选择一名玩家。
  • 玩家更名或唯一标识符变化由管理员核对身份后处理，参见本页账户迁移。

收入与支出

流水类型含义影响历史总收入
ADMIN管理员命令由命令的布尔参数决定
CHECK_IN每日签到收益是
EVENT_CHECK_IN活动签到的贡献值奖励是
DEVELOP服务器建设度奖励只增加余额和历史总收入
SHOP_BUY商店购买扣款否
SPEND消费扣款（股票买入使用此类型）否
STOCK股票卖出到账否
BONUS额外收益按调用方指定
EXTERNAL外部模组调用按调用方指定
REFUND退款（含股票退市返还）否，始终为 0
TAX收税扣款按调用方指定

退款会增加余额，但完全不影响历史总收入。它是一笔新的业务操作，必须使用新的幂等标识符，不能复用原扣款操作的幂等标识符。

查询余额与流水

命令权限功能
/contribution query所有玩家查询自己的余额和历史总收入
/contribution query <玩家>管理员查询指定玩家的余额和历史总收入
/contribution accounts管理员以聊天分页方式查看所有玩家的账户情况
/contribution history所有玩家查看自己的流水记录
/contribution history <玩家> / history *管理员查看指定玩家或全服流水
/contribution history-search <范围> <条件…>自己 / 管理员可查他人或全服按类型、来源、子服与时间范围筛选流水

<玩家> 支持目标选择器、玩家名称或唯一标识符；目标选择器必须恰好选中一名玩家。流水查询默认按 created_at、record_no 倒序排列并使用二者组成的游标分页，不使用大偏移量分页。

  • 默认每页 20 条，单次请求最多返回 100 条。
  • 普通玩家默认最多查询最近 90 天的本人流水。
  • 管理员单次查询范围最多 365 天，可查询归档表；仅指定 from 时向后补足 365 天，仅指定 to 时向前补足 365 天。
  • 筛选条件写作 名称=值，支持 type、source、server、from、to；from/to 为 UTC 的 YYYY-MM-DD 且包含 to 当天。
/contribution history-search self type=EXTERNAL from=2026-09-01
/contribution history-search * server=survival to=2026-09-28

数据库统一以 UTC 保存时间，图形界面按配置的 rewards.timeZone 显示为 MM-dd HH:mm（默认 Asia/Shanghai）。但筛选条件的日期始终按 UTC 日界线计算，界面会注明这一区别。

排行榜

余额、历史总收入、总建设度和各行业建设度可在公开排行榜中查看。每榜显示前 100 名，数据缓存 15 秒。

数值规则

项目规则
代币类型整数
账户余额不允许为负数，范围 0 至 231-1
历史总收入范围 0 至 231-1
单次数量变动-231 至 231-1
原因 / 备注长度各最多 64 个字符
来源标识长度最多 128 个字符

历史总收入默认累计除退款外的所有正向代币变动，负向变动不影响它。管理员命令或外部接口可以显式指定本次是否影响历史总收入：指定 true 时，正向变动增加、负向变动减少相同数量；指定 false 时不改变。退款始终不影响历史总收入。

管理与数据

管理员增减余额
/contribution add <玩家> <数量> <原因> <影响历史总收入:true|false> [备注]
/contribution remove <玩家> <数量> <原因> <影响历史总收入:true|false> [备注]
  • add 增加余额，remove 减少余额；除备注外其余参数均为必填。
  • 布尔值为 true 时，add 同时增加历史总收入，remove 同时减少历史总收入；为 false 时只改变余额。
  • 管理员不能绕过余额范围和数量范围限制。
  • 每次命令先返回请求标识符与可点击的原请求重试文本，再异步执行。
  • 成功执行后，operator 记录为 command-<执行者>，source 记录为 contribution:admin_command。
  • 余额变动通过管理命令提交，图形界面用于查询。
幂等与重试

每次操作都具有全局唯一的流水标识符与幂等标识符，流水表分别为这两个字段建立唯一约束。幂等检查、账户行锁、余额校验、账户更新与流水写入必须在同一个数据库事务中完成。

情况系统行为
幂等标识符不存在执行操作
操作已经完成返回原操作结果，不重复修改账户
操作正在执行异步调用等待事务结果；IN_PROGRESS 仅作为兼容状态保留，不主动返回
操作失败且事务已回滚使用原幂等标识符重新执行
⚠
重试必须原样重发网络超时或结果不明时，只能使用完全相同的请求与原幂等标识符重试。同一幂等标识符对应的目标、数量、类型、来源、原因、备注或历史收入标志发生变化时，返回 IDEMPOTENCY_CONFLICT。管理员的 /contribution retry 和商店的 /shop retry 就是这一规则的命令入口。
流水的归档
  • 在线流水表至少保留一年；超过一年且已完整过期的 UTC 自然月会搬入同库的 contribution_transaction_archive。
  • 归档在主服务器游戏时间 8:00—18:00 运行，每 600 游戏刻最多搬移 500 条；复制与删除处于同一事务。
  • 流水与幂等标识符永久保留，归档记录仍可由管理员查询，但不参与普通玩家的即时分页。
  • 未完整过期的月份暂留在在线表中。
创建账户与唯一标识符迁移

/contribution account create <UUID> <玩家名称> 仅当该唯一标识符尚无账户、该名称也未被其他唯一标识符占用时创建余额与历史总收入均为零的账户。名称冲突不会静默绑定到错误唯一标识符，而是提示管理员先核对旧账户。

/contribution account migrate <旧UUID> <新UUID> confirm 把旧唯一标识符的账户与全部关联数据转到新唯一标识符。

  • 仅允许在主服务器控制台、该服务器没有在线玩家时执行。群组服运维还应先停止其他子服、备份共享数据库并处理完结果不确定的交易。
  • 目标唯一标识符可以没有账户；若已存在，必须是完全空白的账户。有任何余额、历史收入、流水、统计、股票交易、持仓或返还都会拒绝，不会覆盖或合并。
  • 迁移在同一数据库事务和行锁中更新账户、在线与归档流水、玩家统计、交通距离余量、股票持仓与交易、批量请求和退市返还，并写入 account_uuid_migration 审计行。
  • 迁移后，旧唯一标识符发出的未完成请求不应继续重试。
假人账户清理

/contribution bot_check 在一笔数据库事务中找出当前名称仍为 bot_ 前缀的账户，并删除账户及该唯一标识符的流水、玩家统计、股票持仓与交易、退市返还、签到、商店与奖励记录。

✖
这是破坏性操作该命令不会回滚已经计入服务器全局建设度的历史汇总，清理后也无法从模组内恢复被删的玩家记录。执行前必须备份数据库。非 bot_ 账户不受影响。
