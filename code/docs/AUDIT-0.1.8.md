## 已落实的正向设计

| 模块 | 原问题 | 改进 |
| --- | --- | --- |
| 数据库生命周期 | 重复启动重建连接池，关闭持锁等待启动线程，shutdownNow 丢弃任务留下 pending Future | 单启动 Future、STOPPED 终态、锁外等待、任务拥有完成结果、排队任务明确失败，捕获提交时连接池 |
| 贡献页面状态 | 页面/模式/版本/在途请求分散在六个集合，关闭重新打开时存在旧回调身份混淆 | 单个 PageSession 集中管理；结果同时匹配会话对象与页面版本；关闭/离服清理 |
| 请求限流 | 缓存超过阈值时在请求热路径扫描全部历史玩家；停服未重置全服计数 | 离服按 UUID O(1) 清理，取消热路径全表扫描，停服重置桶和全服状态 |
| 原版图表 | 极值采样后按序号等距绘制，陡变漏连接，两次流式统计极值 | 一遍统计价格区间，按游戏日定位，共用整数连线，固定80×32像素存储 |
| 批量股票 | 文本去重允许1和01重复指向一只股票 | 数值 HashSet 去重，O(k)；保留原文本用于兼容请求摘要 |
| 规则捕获 | 逐事件校验重复读取并解析整个内置 JSON，主线程重载产生重复 I/O 与近 O(e²) 解析 | JAR 内置映射一次解析、不可变共享；外部数据包覆盖仍独立重载校验，逐事件 O(1) 查找 |
| 风格与文档 | 排版/旧版本描述分散，命令表易漏分支 | 固定格式化器与 check；真实命令树导出71条路径，HTML/XLSX同源，源指纹+输出哈希强制同步 |

## 保留的性能和一致性约束

- 游戏事件只校验和聚合，数据库默认2线程、1024排队位；高频统计不是每事件一条 SQL。
- 统计最多50000键、恢复日志64MiB，100tick或500脏键刷批；距离余数与统计批次原子入库。
- 日结算主服执行，关日屏障、规则快照哈希、租约与幂等 ID 不变。
- 商店目录最多256件，图标解析有缓存；SQL后台、交付主线程、组件不降级成普通物品。
- 全历史股价流式扫描 O(h)，内存/网络绘图点≤512；目录曲线批量查询，UI逐帧不查 SQL。
- 账户/交易行锁和流水幂等不变；纯样式重构不改变原版客户端兼容性。

## 明确未消除的风险和后续工作

- 持仓加权成本仍按用户历史交易重放，时间 O(t)，不是常数。增量物化需新迁移、历史回填与事务一致性设计，本轮不加短寿命缓存掩盖问题。
- 持平颜色的旧价回溯可能增加逐股索引查询，市场上限20只；须以慢查询量度后决定批量 SQL 重构。
- 每秒市场时钟发布和跨服读仍有数据库负载；不能把同步周期改长而破坏交易时段准确性。
- 背包交付与 SQL 无法组成同一原子事务，极端崩溃窗口可能重复交付；已有租约降低并发风险，但不声称严格一次。
- 先前“客户端卡死/连接超时”未获得充分生产复现证据。本轮会话重构和生命周期测试不等于确认原始卡死根因已消除。
- 不提供未经实测的 MSPT 降幅。上线后应记录玩家数、数据库延迟/慢查询、队列拒绝、统计日志增长、客户端/服务端同期异常。

## 验证方法

新增 `verifyDatabaseLifecycle`：单启动、可用时重复启动、队列满拒绝、关闭中断、排队 Future 终态、停止后拒绝重启/读取。
新增 `verifyStockChart`：稀疏游戏日的真实横轴、同像素列陡变连通、单点及空历史。
原有 `check` 覆盖账户、持久化、统计、距离、股票、奖励、配置、原生 Dialog、滚动条、资源及物品组件；新增格式与文档校验。
文档导出检查每个实际可执行路径均有说明；两个工作表经 inspect 和 PNG 预览确认，公式错误匹配为零。最终构建结果以构建日志为准；真实 MySQL 和真实客户端人工验收需单独记录。
