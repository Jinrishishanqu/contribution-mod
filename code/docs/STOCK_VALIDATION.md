# 股票系统 0.0.2 验证记录

验证环境：Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.161.0+26.3、Java 25、H2 2.5.250、项目专用 MySQL 8.4.6。

最终构建文件为 `build/libs/CSU-YSU-contribution-system-0.0.2.jar`，SHA-256：`D3A2C7390EC9014B91811AC9C98348454B2010B151F2D9747C8CC6C46F995AA6`。

`run-gradle.ps1 build --offline` 成功；`verifyEmbeddedStocks` 在新建的世界文件数据库内验证 V8 建表、30 支股票覆盖九行业、买卖和 2% 手续费、当日买入不可卖、每日交易次数、重复请求只成交一次、余额不足及持仓超限拒绝、曲线输出、主服务器时钟过期后暂停交易、退市返还不增加历史总收入。`verifyDialogs` 对实际曲线文本、数量输入框和交易命令模板完成原版 Dialog JSON 与网络编解码往返。

`verifyMySqlStocks --offline` 在真实 MySQL 8.4 InnoDB 中通过相同股票交易流程。测试使用随机命名的独立数据库，在运行结束并关闭连接后清理，不接触玩家世界或正式数据库。

使用打包后的单一服务端 JAR 启动真实 Fabric 服务器，日志确认加载 `contribution 0.0.2`、从既有 V7 迁移到 V8、数据库连接可用；测试库随后查到 `stock_market_state` 已推进、`stock_listing` 有 30 支股票。测试服务端无需客户端模组。

验证边界：没有真人客户端逐页查看字形和按钮布局；曲线的可传输性已验证，但具体视觉效果仍会随玩家字体及资源包变化。没有多台物理服务器同时高负载切服的长期试运行，也没有在生产备份上验证升级。正式群组服上线前应备份 MySQL 并安排试运行。

`verifyEmbeddedStocks`、`verifyMySqlStocks` 与完整 `build --offline` 通过；测试包含奇数价格阈值和十倍价格上限边界。0.0.7 分发 JAR 在 Minecraft 26.3 / Fabric Loader 0.19.5 / Fabric API 0.161.0+26.3 / Java 25 服务端加载，连接项目 MySQL 8.4 测试实例、确认数据库 V14 并正常停服。最后一次构建仅收紧客户端双击判定，未再修改服务端逻辑；最终 JAR SHA-256：`7CB2805A0A8B08AB596B51CB0687366BBB4192F4AF07A25D869149E28DC3F15F`。

## 0.0.8 曲线、逐行按钮与阈值更正

收到客户端截图后，0.0.7 的自绘复选框和双击行在实际游戏中仍无法可靠操作。0.0.8 为每个可见股票行注册两个原版按钮控件，分别用于单击勾选和直接打开详情；自绘部分只负责外观，并保留坐标点击兜底。陡峭价格变动改用连通的整数像素线段及裁剪后的 2 像素笔画，回归检查断言从 `(0,0)` 到 `(3,40)` 的线段覆盖每个纵向像素且相邻像素不跳跃。

退市阈值按用户更正改为 `max(⌊初始价/2⌋, ⌊历史最高价/4⌋)`；结算和两种客户端显示仍共用 `StockPricing`。`verifyEmbeddedStocks verifyMySqlStocks build --offline` 均通过。0.0.8 分发 JAR 在 Minecraft 26.3 / Fabric Loader 0.19.5 / Fabric API 0.161.0+26.3 / Java 25 服务端启动至 `Done`，连接项目 MySQL 8.4 测试实例、确认 V14 数据库可用并正常停服。最终 JAR SHA-256：`863E461E04FD40D52BA9352432FAB5A9322A52DF9BD2C61CE52A4A0F12ACDCF3`。

尚未在实际安装 0.0.8 的客户端逐项点击这两个按钮并检查曲线截图。服务端和自动测试通过不等于客户端人工验收通过。

## 0.0.9 界面布局与细线

用户截图证实 0.0.8 的 2 像素笔画在高 GUI 缩放下过粗，独立“详情”块挤占了名称/行业列，详情内容与交易栏重叠，行业菜单仍无法可靠勾选。0.0.9 将陡坡线改为单像素、四邻域连通光栅；名称/行业区域作为详情点击区，勾选框独立对齐；行业选项注册原版按钮并保留浮层优先处理。详情页使用裁剪的滚动内容区与固定交易栏，历史图表至少高 110 GUI 逻辑像素。自动测试验证线段逐点连通；实际客户端的点击、滚轮和不同 GUI 缩放视觉仍需人工验收。

Java 25 下 `verifyEmbeddedStocks build --offline` 通过，包含 57 个 JSON 资源及 45 个玩家标签检查。分发 JAR 在 Minecraft 26.3 / Fabric Loader 0.19.5 / Fabric API 0.161.0+26.3 服务端加载到 `Done`，临时测试世界的嵌入式数据库从 V6 迁移至 V14 并正常停服；测试世界原有 MySQL 配置随后恢复。本轮未重新启动 MySQL 实例，不能将此次服务端验证称为 MySQL 联调。0.0.9 JAR SHA-256：`7E286FA381FB89C7C762F3167C3510FF511746ED9252C1F43E89824034747538`。

## 0.0.10 返回交互与时间轴

用户实测发现 0.0.9 从详情页返回市场后，行控件有自绘悬停反馈却不能点击。原因是旧市场屏幕对象被复用、再次初始化时旧按钮引用未清空，导致新注册的按钮在可见性同步中被隐藏。0.0.10 返回时创建新市场屏幕并复制本次会话状态，初始化先清空按钮列表；详情/个人页 Esc 返回市场，市场页 Esc 清除会话。刷新保留状态，完全退出后再进入重置。持平日颜色由最近一次非零价格变动决定；市场小图使用以当前游戏日结束的固定 30 日横轴。嵌入式股票回归增加涨跌方向和固定横轴端点断言。客户端实际点击与 Esc 流程仍需真人验收。

补充长期持平场景：如果 30 日曲线没有非零变化，服务端从历史价格索引取得最近一个不同股价，只传方向、不把旧价格加入图表。嵌入式数据库回归构造 39 个连续持平日，确认市场仍展示 30 日数据而市场/7 日详情都保留更早的上涨颜色方向。`verifyEmbeddedStocks build --offline` 已通过；本轮新增查询尚未在独立 MySQL 实例中重跑。

同版本后续整理：市场首列改为三行左对齐信息与小型详情按钮，行/行业选择共用单一复选控件。行业选项在行控件之后注册，保持浮层绘制与点击优先；详情曲线移到顶部，默认 360 日并提供 7/30/360 日及全历史四种范围，横轴显示起止与中间游戏日。全历史查询在数据库工作线程执行，并将绘图点限制在 512 个，保留首尾和每个时间桶的极值。新增千点采样与数据库全历史回归；`verifyEmbeddedStocks build --offline` 再次通过。真实客户端上的返回、点击、鼠标悬停、下拉和 GUI 缩放仍未人工验收，不能据此宣称截图中的问题已经完全消失。

0.0.11 为市场、个人持仓、详情三种超长内容加入可点击、拖动的滚动条，继续支持滚轮。其轨道、滑块比例、端点和中间定位使用纯几何回归检查；“股数”标签在交易栏内移至输入框左侧。实际客户端拖动操作仍待验收。
