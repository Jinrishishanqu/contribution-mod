# Basic 0.0.1 验证记录

验证日期：2026-09-29。环境为项目内 Java 25、Minecraft 26.3、Fabric Loader 0.19.5、Fabric API 0.161.0+26.3、H2 2.5.250 与 MySQL 8.4.6（仅绑定 127.0.0.1:23306）。所有世界、数据库和工具均为本项目测试用途。

最终构建产物为 `build/libs/CSU-YSU-contribution-system-0.0.1.jar`，SHA-256：`6E2A20B55253DE957BE0D6AB477810EDB868E6FDBAFD1D0408B4C787443E2F5E`。

## 自动化检查

`run-gradle.ps1 build --offline` 执行：

| 检查 | 覆盖范围 |
| --- | --- |
| verifyResources | 57 个 JSON 可解析；45 个玩家标签的注册 ID 均存在，同动作不重复归类，可逆合成物品未进入 craft |
| verifyAccountQueries | 查询条件、非法输入、日期边界、分页游标 |
| verifyDistanceAccounting | 16 格阈值、跨批余数、阈值变化、超大整数安全换算 |
| verifyDialogs | 实际页面构建器的文本、输入框、按钮、命令模板通过原版 JSON 与网络编码往返 |

`verifyDatabaseIntegration` 在真实 InnoDB 中验证迁移、余额与总收入边界、退款不计收入、离线名称查询、并发增量不丢失、并发相同请求只入账一次、内容冲突拒绝、余额不足不记流水、自然月归档、历史日期查询及归档后幂等重试。

`verifyStatisticsIntegration` 验证批次重复提交、15.5 格加 1 格只形成 1 点并保留 0.5 格、服务器与玩家建设度同时提交、规则哈希冲突时回滚批次标记、两日为零的 EMA 初始化、上限饱和及规则 JSON 哈希往返。

上述数据库测试都已通过。测试中主动触发最大值饱和时的 ERROR 日志为预期断言场景，不是测试失败。

## 实际服务端验证

开发服务端和 `verifyPackagedServer` 均已启动至 Done，并连接 MySQL。后者直接加载构建出的分发 JAR，不使用开发 classes 目录；连接池、驱动和 Flyway 从 JAR 内嵌依赖加载。全部 Mixin 目标类通过启动加载检查。

在项目测试世界进行了以下操作：

- 使用真实熔炉烧炼一个铁矿石，数据库采矿冶金当日建设度增加 1；将采集点收窄到烧炼完成调用后再次验证，仍增加 1。
- 推进游戏时间跨过 8 点，生成九个行业的每日记录；采矿冶金的 1 点正确进入累计总量。
- 主服重载测试数据包：当日规则哈希不变，下个游戏日切到新哈希；禁用测试包后，下个游戏日恢复默认规则。
- 首个不完整日、首个完整日 EMA 为空；第二个完整零值日结束后 EMA 为 0、繁荣度按公式为 -1。
- 分发 JAR 服务端执行两次相同幂等 ID 的管理员命令，最终余额与总收入均为 100，只有一条 +100 流水；随后扣除 101 被拒绝。

测试数据包仅在 `code/run/world/datapacks/contribution-basic-test` 中保留为复现材料，验证后已禁用，不进入分发 JAR。开发测试配置指向独立本机测试库；打包默认配置现已改为自动创建本地文件库。

## 本次修正的验证问题

初始 V1 脚本曾对 AUTO_INCREMENT 列添加 MySQL 不允许的 CHECK，已在正式发布前修正。规则初始化移到 SERVER_STARTED，避免主世界尚未创建。普通合成、锻造和铁砧的 Shift 点击路径保留实际转移数量，避免结果堆叠被原版清空后漏计。熔炉监听从每 tick 拷贝物品改为仅在产出时处理。

## 零配置数据库补充验证

单人和单服现在默认使用随 JAR 内嵌的 H2 文件库。`build` 增加本地数据库首次迁移、账户并发与幂等、余额边界、退款、流水归档、统计批次、建设度、距离余数及重启持久化检查，均已通过。旧配置中 `enabled=false` 自动解释为本地模式，`enabled=true` 自动解释为 MySQL；显式 `mode` 优先，配置兼容性检查已通过。

使用最终分发 JAR 在项目测试世界启动至 Done：H2 文件 `world/contribution/contribution.mv.db` 自动创建、六个迁移成功、数据库可用。随后重新启动相同测试世界，Flyway 确认结构为第 6 版并无需重新迁移；通过控制台 `stop` 正常停服。打包 JAR 中 H2、MySQL 驱动及迁移依赖均已成功装载。初次验证进程曾在数据库提交后强制停止，第二次启动也完成了文件库恢复。

原有 MySQL 账户和统计集成测试在 8.4.6 上再次通过。另用新建且随机命名的项目测试库验证：主服务器在具备建库权限时自动创建数据库，并执行六个业务表迁移；测试结束后该随机测试库已删除，项目 MySQL 已正常关闭。MySQL 服务本身不会由模组安装或启动，群组服仍需提供共享 MySQL。

Flyway 13.5.0 对 H2 2.5.250 给出“版本较新、尚未列入其已验证版本”的提示；上述真实迁移与重启测试均通过，但后续升级 Flyway 或 H2 时应继续做兼容性回归。

## 验证边界

没有真人客户端逐页视觉验收，也没有把所有玩家动作逐项在游戏内操作一遍；图形页面已验证原版编解码，但不把这等同于屏幕截图验收。单机真实数据库并发与单服关日已验证，多台真实服务器同时切服、极端崩溃注入及长时间高负载仍需正式部署前的试运行。它们不是额外玩法设计待定项。

## 0.0.10 股票界面回归

客户端页面返回时不再复用旧按钮集合；详情/个人页 Esc 返回市场、市场页 Esc 退出并丢弃筛选状态。市场曲线按固定 30 游戏日横轴定位历史价格；当日 0% 涨跌沿用最近一次非零涨跌颜色。Java 25 下 `verifyEmbeddedStocks build --offline` 已通过；客户端输入与布局仍待实际游戏验收。

长期持平颜色方向另经 H2 数据库回归：市场曲线仅含最近 30 日，但更早的最近一次不同股价仍能决定配色；详情 7 日范围亦如此。此新增历史查询本轮未在 MySQL 实例重新执行。

同版后续修正将股票名称、行业和小型详情按钮改为三行左对齐；列表与行业筛选采用尺寸稳定的单一复选控件，行业浮层控件最后注册。详情曲线置顶并增加游戏日横轴，默认 360 日，可切换到全历史；服务端在数据库工作线程读取并将全历史绘图点限制为 512 个。新增 1000 点抽样与完整日跨度测试，Java 25 `verifyEmbeddedStocks build --offline` 再次通过。此后的 UI 改动尚未在实际客户端截图和鼠标操作验收，也没有重跑打包服务端启动。

## 0.0.11 界面与时间显示

Java 25 执行 `build --offline` 通过，含 57 个 JSON 文件与 45 个玩家标签检查、原生 Dialog JSON/网络编解码、表格列宽以及滚动条几何回归。随后补齐同版界面：安装模组的客户端可打开贡献值账户、流水、统计和行业建设度的固定像素列表；原版客户端仍使用 Dialog。流水每笔一行，时间缩至月日与时分，验证 UTC 时间在北京时间显示正确。股票原版后备页面增加涨跌、退市阈值、持仓与常用排序；商店客户端布局压缩，避免商品详情与购买控件重叠。完整构建再次通过，但未在真人客户端逐项验证滚动条拖拽或各缩放比例的实际屏幕效果；没有对现有世界或 MySQL 生产数据做迁移。

## 0.1.1 主世界时钟

主服世界钟与已核算股市日拆分为两个数据库字段组；主服即使日结等待也继续记录观察时钟，子服每秒至多查询共享数据库一次并向本服客户端推送。刷新、原版 Dialog 和交易校验都使用同一主服观察时钟。回归测试覆盖观察日领先核算日时的明确拒绝交易、5 秒过期时钟拒绝交易和 V15 新库迁移。Java 25 的 `build --offline` 已通过。未连接用户生产 MySQL 或在真实群组服观察跨日，因此实际缺少的统计服关日记录仍须由服务器日志和部署配置核实。
